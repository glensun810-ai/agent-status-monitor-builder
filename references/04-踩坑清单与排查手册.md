# 04 · 踩坑清单与排查手册

> 按「现象 → 根因 → 处置 → 预防」组织，全部来自真实排障。排查顺序建议：先跑只读体检，再按本表定位，最后才动代码。现役口径为 W29（2026-11-16）。

## A · 环境与部署

**A1 · 服务起不来 / 读不到项目文件**
现象：launchd 启动后静默失败，日志无报错。根因：macOS TCC 不给 launchd 读 `~/Documents` 的权限。处置：运行时统一从 `~/.workbuddy/wblight/` 镜像加载；由同步脚本保证与真源逐字节一致。预防：把「运行时注册点在目录外」写进 README 边界，不做零镜像幻想。

**A2 · 手工搬目录后 hook 报错、`.git` 消失**
现象：整理文件夹后链路断、版本库不见。根因：hooks 软链 / plist 指向绝对路径，移动即失联。处置：恢复软链与 plist 指向，重跑链路自检（113 项）。预防：路径只改 `paths.json`，用 `--apply` 同步；禁止整目录手工搬移。

**A3 · 批量替换 `.workbuddy` 路径**
现象：替换后状态灯彻底不响应。根因：链路 py 里的这些路径是**镜像内部运行时路径**（状态 / 令牌 / 日志 / 锁 / 事件流水），不是外部依赖。处置：从 `02-状态灯链路/` 源副本恢复，必要时 `--sync-links` 显式下发。预防：源码副本只做版本管理，不做路径「清洗」。

**A4 · 8080 端口不通**
现象：体检端点 FAIL。根因：服务进程退出、镜像与真源不同步，或较早阶段 `launchctl bootstrap/load` 在当前 namespace 失败。处置：先查 launchd 服务状态（`launchctl print` / 进程 pid）与镜像同步状态；参考实现现役 8080 为 launchd 常驻（`RunAtLoad` + `KeepAlive(SuccessfulExit=false)`，kill 后 12s 自动拉起实测通过），旧 临时 keepalive 脚本 已退出无残留。预防：体检报告里区分「服务未跑」与「代码故障」，不盲目重启；若曾依赖临时 keepalive，切换前先备份 plist 并准备回滚。

**A5 · IP 漂移后手机打不开**
现象：收藏的 `192.168.x.x` 失效。根因：DHCP 重分配。处置：改用固定 `.local` 域名；页面调 `/net` 显示当前 IP；W29 换网向导按 `/net` + `/api` 真值判同网并给出救援 AP。预防：IP 只写 `network.json`，永远不硬编码进 HTML。

## B · 前端与数据

**B1 · 偏好调好重进被重置（最典型）**
现象：三色滑块调好，刷新后回默认。根因：`savePrefs()` 无 rgb 字段、`commitRgb()` 只下发硬件不落盘、`setState('RUN')` 早于 `loadPrefs()`；更隐蔽的是 `init()` 里 `setRange('24h')` / `autoProbe` 在恢复之前就调 `savePrefs()`，把偏好覆写成 `rgb:null`。处置：`savePrefs()` 改成**合并语义**（先读旧值，`rgb:DEV.manualRgb?DEV.rgb:(old.rgb||null)`），恢复段早于 `toggleLock()` 等回写。预防：只改「存 / 读」不做合并，静态断言会全绿、刷新仍丢值 —— 必须跑真浏览器往返。

**B2 · 静态断言全绿但功能没验到**
现象：老基线 504 项全 PASS，新功能却坏的。根因：老断言不覆盖新代码。处置：每个新功能建独立专项（`bl=False`），并做真浏览器往返。预防：把「老基线全绿 ≠ 新功能已验」写进验收清单；W29 方案 §7 更用「缺席探针」把未落地项固化成可检测事实，补实现后探针 FAIL 强制同步断言与留痕。

**B3 · 手机刷新拿不到新页面**
现象：改了 HTML，手机还是旧版。根因：SW 缓存名没 bump。处置：bump SW 缓存名（现役 `wb-board-w29-v1`）与 `budget_revision` 同步更新。预防：把缓存名一致性纳入体积 / 预算断言；运维负责人目视确认手机换到新缓存。

**B4 · 公网静态站误报「连接中断」**
现象：线上预览页一直显示断线红条。根因：静态站无后端，却执行了本地服务的探活逻辑。处置：按 `env=static` 分支降级为连接向导页，只做环境识别与入口指引。预防：无后端就诚实说明，不造演示数据。

**B5 · 某来源计数恒为 0**
现象：TRAE CN 一直 0。根因：8080 `_derive_event()` 三处把 `src` 写死，`/api.agsrc` 只有 top 来源。处置：改为取 `/agents` 明细按本轮 `ago` 最小归属（短超时 + 好值缓存，失败回落 `agsrc`）；`/stats` 增 `trae` 并保留 `tree` 兼容别名。预防：来源归属必须基于明细，不要用聚合值猜；命名铁律只认 **TRAE CN** / 短码 `trae`。

**B6 · 板端离线时来源计数为 0 被当成 bug**
现象：体检或页面显示 0。根因：`/agents` 不可达属正常环境态。处置：如实显示 0，等板端恢复且有真实活动才有计数。预防：环境态记 WARN，不伪造数据、不判 FAIL。

**B7 · `CANON_BASELINE` 失配**
现象：体检报基准哈希不符。根因：改了功能代码。处置：重算并在 `VERSION.md` 留痕（写明前后值）；仅删空白 / 注释不应改变该值。预防：禁止直接改常量「让它变绿」；W29 的哈希链共 8 个值，全部在编年史留痕、原文不回改。

**B8 · 对齐断言偶发抖动**
现象：`/align` work 子态 `waiting` vs `generating` 不一致。根因：Agent 运行时状态切换竞态，非程序故障。处置：静置或独立复跑；体检内置隔 2s 复跑一次，通过记 WARN。预防：不把瞬时竞态升级为代码改动 —— 但先排除 B10 那种「其实不是竞态」的情况。

**B9 · 状态反馈完全不显示 / 台账写「已补齐」但 DOM 里没有（假绿断言）**
现象：W29 A4 验收发现多行设置保存无就地反馈；查台账却记「5 个独立 id 已补齐」。根因：6 个 `dsStLayout/dsStSleep/dsStRot/dsStNight/dsStNightR/dsStPower` 只作为 `patchConfig` 的 `elId` 出现在源码，DOM `[id^="dsSt"]` 实测只有 `dsStBright`；`verify_w29` F 段两条断言**只校验源码字面量、完全不校验 DOM 存在性**，其中一条标题还明写「无 DOM 元素时仍由 ovSaveTag 兜底」⇒ P0 阶段是有意悬空。处置：6 个 elId 统一改指真实存在的 `ovSaveTag`；F 段改为真契约，新增 P 段通用断言「正则提取全部 `patchConfig` 状态 elId，逐个比对 DOM `id` 集合，任一悬空即 FAIL」。预防：任何「元素 / 状态 / 配置」类断言都要碰到真实对象；勿把「源码里有这串字」当验收。诚实边界：6 行仍共用全局状态位，不是逐行就地状态。

**B10 · 「点完按钮元信息不变」，被误判成竞态**
现象：W29 A4-① 设「紧凑」后按钮态与 `data-density` 都变了，预览元信息恒为「丰富」，等几帧也不联动。根因：刷 `dsMetaL` 的逻辑在 `renderMode()`，而 `setLayout()` 末尾调的是只重绘 OLED 的 `frameV2()` —— **调用错函数，不是竞态**。处置：`patchConfig(...)` 后保留 `frameV2()`、补调 `renderMode()`（`patchConfig` 同步且 `renderMode` 不反向调用，故幂等无竞态）。预防：先定位「谁真正写这个 DOM」，再决定是否加延时 / 复跑；把 `frameV2();renderMode();` 同链写成断言。

**B11 · 压缩后断言大面积失配**
现象：安全空白压缩删 3,067 个换行后，按 `\n}\n` 提取函数体的断言取不到内容。根因：函数结束形如 `}function …`。处置：`verify_w29` G 段与 `verify_w25` C 段改为「以下一个 `function` 定义锚定」，兼容压缩前后；`}).catch(...)` 里的 `}` 仍须避开。预防：压缩器用 AST / 断言字面量保护，删完复跑全部 `verify_*.py` 与三段内联 JS `node --check`；深色变量原文无空格（`--on-bg:#3a4656;--on-fg:#fff`）也别按宽松正则写。

**B12 · 体积逼近护栏，按理论空白量报价导致返工**
现象：W29 P1 完整落地 200,738 B，超硬上限 196,000 B，脚本按设计 ABORT；运维负责人曾按「纯空白 8,180 B 可释放」估算，实测安全压缩上限仅 **3,077 B**。根因：理论空白大半是属性分隔 / 文案 / CSS 值，删不得。处置：运维负责人拍板 A 方案 ①「先落地后压缩 + 精简 P1 新增代码」：先按未压缩页面做 7 处精确替换，再缩短文案、合并 `heatSVG()`、省 `</option>` 闭合，最后 `w29_compress.py --apply`。预防：护栏 200,000 B 与 `min_headroom_bytes` 4,000 B **不放宽**；报价用实测值；现役余量 4,034 B ⇒ 可新增上限仅 **34 B**，任何新增 DOM 都要先腾预算。

**B13 · 向导承诺网页配网 / 热力图画了没有数据的月季图**
现象：用户以为前端能改 WiFi，或月/季视图一片空白被当成 bug。根因：固件已主动砍掉网页配网（SSID 硬编码 `config.h`）；真实事件仅约 2.43 天。处置：向导写明「换 WiFi 须改 `config.h` 重编译烧录」，只做同网判定与救援 AP 指路；热力图只做四维度，按首末事件算**真实覆盖天数**并标注「数据积累中，暂不绘满」，空维度显示「该维度暂无事件 · 不绘制推测数据」。预防：月/季聚合须先做「事件按月归档」前置（格式 / 切割时点 / 保留期 / 跨月聚合 / `dur_s` 口径），属 P2′，范围已报价获运维负责人拍板、另开会话立为 W30 执行。

## C · 硬件与验收

**C1 · 预览红绿反色 / 颜色口径不一致**
现象：页面预览与实物灯颜色相反。根因：固件与前端颜色映射不同。处置：修固件并烧录；同时撤销门户侧临时的 `k_fw` 交换（A/B 方案互斥）。预防：以后再烧固件切勿恢复已撤销的交换开关。

**C2 · 亮度掉电丢失的误判 / 把 `wb_bv` 当总亮度**
现象：怀疑「没接电脑就不保存」，或前端把「音量」接到总亮度。根因：混淆两条链路 —— 浏览器偏好在 `localStorage`，硬件参数在固件 NVS（`wbSaveParams()` / `wbInit()` 读回）；`wb_bv` 是蜂鸣器/功放音量，硬件只有 b/g/r 三色百分比，`light.brightness` 是软件缩放系数。处置：以冷启动 `/api` 回读 `nvsok` 与 `wb_b/g/r/bv` 实证（实测 `nvsok=1`、参数 ≠ 出厂默认）。预防：文档里明确「本轮未碰固件」≠「固件没有该功能」。

**C3 · 无心跳却显示蓝 / 绿**
现象：板子还亮着旧状态，误导人以为在线。根因：缺失效保护。处置：保留 `wbstate.h` 无心跳强制灭灯（运维负责人拍板「保持灭灯」）。预防：灭灯逻辑是安全设计，不要为了「好看」删掉。

**C4 · 烧录失败**
现象：串口写入失败。根因：数据线只能供电不能传数据。处置：换 Type-C 数据线直连；整片备份 → 只写 `0x10000` → 读回 md5 一致 → `/api ver` 回读一致。预防：`flash.md` 写清前置检查与回退路径。

**C5 · 中文 OLED 乱码 / 截断**
现象：中文字符被切成半个。根因：按字节裁剪破坏 UTF-8 字符边界。处置：按字符边界裁剪（参考 `w8DrawU8()`）。预防：显示缓冲与消息保持时间（`W8_MSG_HOLD_MS`）一起校验；推送文本守 W27 ASCII 短码（板端 `gW8.msg[32]` 仅 31 字节），T/A 含义在 toast 解释。

**C6 · 把人工验收写成 PASS**
现象：报告里三入口颜色「已验证」但没人看过。处置：验收清单单列「需人工在场项」：按键红双闪 + 滴滴声、OLED 双屏并排目视、真机断电重启验自启、`--act` 实板下发、iOS 安全区 / 深色 / 320–430px 目视、手机刷新换 SW。预防：脚本不代签、不伪报；W29 P1′ 12 项由运维负责人本人回报全 PASS 后才销项，C4 断电重启后还须回读 8080 / 8420 = 200、本机与板端 `/api` 的 `rst=poweron` / `ver`。

**C7 · 视频渲染与字体**
现象：标题被裁、中文变繁体或方框。根因：视频层按 box 高新建画布、超出静默裁掉；`Menlo.ttc` 无中文字形；`STHeiti Light/Medium.ttc` 的 index=0 是繁体。处置：标题层高度 ≥ 内容底部 + 16px 入场位移；ASCII / 中文分段分流；中文字体取 **index=1**；固定时长画面配音分组变速。预防：先出静帧总览再渲染成片。

## D · 协作与成本

**D1 · 单会话串多个任务导致成本暴涨**
现象：一次会话串 6 个独立任务、反复重发大上下文。处置：一任务一会话；任务收尾提醒新开会话；跨会话用记忆文件传上下文。预防：批量执行相关命令、只读需要的行、一次全量复验，不「跑一步看一眼」。预计 >50 轮 / 读入 >200KB / 3+ 互不相关子任务须先报价等确认。

**D2 · 先重建后诊断**
现象：没看清现状就 `--apply`，把偏差刷进清单。处置：先 `health_check.py`（只读）确认起始状态，再重建。预防：把「体检只诊断、`--apply` 才重建」写进日常命令表；不擅自跑 `--apply`、不擅自重建发布镜像。

**D3 · 现役真值表以为会自动更新**
现象：体积 / 按钮数 / CANON / 专项项数变了，README 第五节还停在旧批次。根因：`sync_runtime.py` 源码 Grep `readme|现役|w29|baseline` 零命中，**不回写 README**。处置：每次真值变动手工同步 README 第五节 + `VERSION.md` 追加留痕；编年史中间值原文不回改。预防：把「手工同步真值表」列为收尾清单的硬性一项；读历史叙述时以 `README` 第五节 + `VERSION.md` 最新章为准。
