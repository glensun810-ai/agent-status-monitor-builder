# 01 · 全流程复盘与学习经验

> 复盘对象：一套已落地的 Agent 状态监控小系统，2026-11-06 起，至 W28（2026-11-16）软件定稿、固件已烧录。
> 用途：给复刻者说明**为什么**会形成现在的架构，避免只抄目录却重踩一遍坑。数值均为该项目现役史实，复刻时按自己的环境重算，不要照抄。

## 一、五个阶段（先看脉络）

| 阶段 | 时间 | 当时的问题 | 关键决策 | 代价 / 遗留 |
|---|---|---|---|---|
| 0 · 硬件探索 | 11-06 ~ 11-10 | ESP32-S3 能不能点亮、OLED/WiFi/音频/传感器怎么接 | 板卡先跑通，逐个外设实测；能力路线图 v1/v2 | 分支极多（鼾声、红外、HA、AI 对话），范围膨胀；曾出现「死代码结论反转」，手工整理目录触发 hook 报错、`.git` 消失 |
| 1 · 状态灯立项 W1–W9 | 11-11 ~ 11-14 | 把「Agent 在干什么」变成看得见的灯 | 建立 hooks → 状态文件 → 哨兵 → 板子链路；v1.0 看板；W8 固件 + 板载 AP 页；固定地址方案、门户访问码 | 前端地址写死、多副本并存；目录被人工搬动导致运行时注册点失联 |
| 2 · 产品化 W10–W13 | 11-15 凌晨 | 演示态 ≠ 真实态；电脑能看、手机进不来 | 重写 v2.0 单文件 SPA；**只用真实数据源**；三方对齐全量验证；11 个 `/ctl` 动作全接通；访问码改 POST `/__pair`；新增 `/net` 动态返回 IP/mDNS | 从「能跑」跨到「可交付」，验证项第一次形成基线（450 项） |
| 3 · 收敛与瘦身 W14–W18 | 11-15 上午 | 121 个按钮真假难辨、旧资产散落、公网静态站误报断线 | 按钮全量排查「不删只修」；W15 删调试控件 + L0/L1/L2 分层；W16 修预览红绿反色并烧录；W17 静态站诚实降级为连接向导；W18 HTML 39 → 12 | 确立了「不造假数据」的产品口径 |
| 4 · 工程化 W19–W24 | 11-15 下午 | 真源不唯一、验证命令分散、SPA 体积膨胀、手机端导航拥挤 | 新建唯一真源目录；`network.json` 单点配置；`sync_runtime.py` 单一同步通道；`INVENTORY.json` md5 清单；`health_check.py` 一键体检；连接退避 + 监控增强；体积护栏与瘦身；4+1 折叠导航；文案规范 | 形成「改代码 → 补断言 → 同步重建 → 一次全量复验」闭环 |
| 5 · 真实报障驱动 W25–W28 | 11-15 夜 ~ 11-16 | 三色调节、屏预览、来源归属、掉电偏好等真实使用问题 | 三色整合；预览联动 + 按键连击；TRAE CN 来源归属改为按 `/agents` 明细归属；OLED 商用化；固件合并烧录（只写 `0x10000`）；三色偏好持久化合并语义修复；亮度掉电 NVS 边界澄清 | 静态断言全绿但真浏览器 6/11 才暴露假绿；人工物理验收仍需人员在场 |

**结构特征**：不是按最初的三期计划线性走完的。三期（体检 → 增强 → 瘦身）在 W20–W22 完成后，W23–W28 全部是使用者逐次提出的新需求 / 真实报障。复刻时应预期「先立骨架与纪律，再被真实使用反复修正」，不要指望一次设计定稿。

## 二、每阶段最值得带走的一条

1. **硬件期**：先做最小闭环（点灯 → 联网 → 收指令），不要同时铺开十个外设分支；每加一个分支都要有实测证据，否则会积累「自以为实现了」的死代码。
2. **立项期**：运行时注册点（hooks 软链、plist、令牌、镜像）一旦手工搬动，链路会静默断掉。把「哪些东西天然不属于源码目录」写进文档，比事后排查便宜得多。
3. **产品化期**：真实数据源 + 对齐验证是分水岭。演示数据能让界面好看，但会让后续每个 bug 都难以定性。
4. **收敛期**：「不删只修」适用于功能排查（保住按钮契约），「果断删」适用于调试控件与历史资产，两者不矛盾，判据是「是否有真实用户路径依赖」。
5. **工程化期**：把验证从「多条命令 + 人记」变成「一条只读体检命令」，并明确区分环境态 WARN 与程序故障 FAIL，系统才可被日常托管。
6. **报障期**：任何「看起来只是存/读」的偏好修复，都要跑真浏览器刷新往返；静态断言查不出初始化顺序造成的覆盖。

## 三、十二条可迁移经验

| # | 原则 | 本项目证据 | 复刻时怎么落地 |
|---|---|---|---|
| 1 | **先立唯一真源，再谈功能** | W19 之前源码、发布目录、运行副本三处并存，改一处漏两处 | 开工即定一个根目录；其它位置一律称「镜像 / 注册点 / 归档」，并在 README 写死 |
| 2 | **配置单点化 + 运行时动态值** | `network.json` 生成页面 `WB_NET` 块；`/net` 返回真实 IP，DHCP 漂移不改代码 | 页面常量用 BEGIN/END 生成块；静态值只当兜底，展示值优先问服务端 |
| 3 | **源码与运行时镜像分离** | macOS TCC 使 launchd 读不了 `~/Documents`，运行时必须用 `~/.workbuddy/wblight/` 镜像 | 接受镜像存在，用同步脚本保证与真源逐字节一致；不要试图把运行时路径批量替换回真源 |
| 4 | **一切改动可回滚** | `INVENTORY.json` 全目录 md5、`--rollback`、W0–W9 全量 zip | 每次重建自动重算清单；新增文件后必须先同步再体检，否则清单偏差误报 FAIL |
| 5 | **断言驱动，且基线不混增量** | 504 项基线（450 + W19 54）；W21–W28 专项设 `bl=False` 不计入基线 | 每个新功能单独建专项脚本；老基线全绿不代表新功能已验，避免「假绿」 |
| 6 | **静态断言 ≠ 运行时正确** | W28 三色偏好：静态全绿，真浏览器 11 项往返在第 6 项暴露 `savePrefs()` 被更早调用覆写成 `rgb:null` | 偏好 / 初始化顺序 / 缓存 / SW 更新类改动，必须跑真浏览器「改值 → 刷新 → 回读」 |
| 7 | **环境态与故障分级** | 板端断电、断网、CDP 未就绪、状态切换竞态一律 WARN；仅代码 / 配置 / 契约 / 清单失败判 FAIL | 体检脚本内置分级与「失败后隔 2s 复跑一次」，复跑通过记 WARN 留痕 |
| 8 | **不造假数据** | 公网静态站无后端 → 只做连接向导、不显示「连接中断」；`/stats.trae` 板端离线时如实为 0 | 任何「取不到」都给未知 / 降级态，不用演示值填坑；人工目视项脚本不代签 |
| 9 | **编年史 + 勘误留痕** | `VERSION.md` 逐版记录决策，旧文原文不回改，冲突时追加勘误头 | 改功能代码导致基准哈希失配时，必须重算并在编年史留痕，禁止静默更新 |
| 10 | **单文件 SPA 要设体积预算** | 护栏 200,000 B / 余量 4,000 B；W21 临时放宽到 220,000，W22 靠剥注释压回 | 护栏写进验证脚本与 manifest；改版同步 bump SW 缓存名，否则手机拿不到新页 |
| 11 | **命名与口径统一** | 官方名 TRAE CN / 短码 `trae`；「Tree CN」「第 N 页」等口径纠正 | 建一份术语表，采集端、服务端、前端、文档同时改；错别字会长期伪装成数据问题 |
| 12 | **物理动作留给运维负责人** | 烧录、按键红双闪、OLED 双屏目视、断电重启验自启、`--act` 真实下发 | 脚本只接好显式开关，不替人触发、不伪报结论；验收清单里单列「人在场项」 |

补充一条协作经验：**一任务一会话、跨会话用记忆文件传上下文**。本项目高峰期因单会话串多个任务、每轮重发大上下文导致积分暴涨；后来固定为「先诊断后重建、批量执行、一次全量复验、收尾新开会话」，成本与出错率同时下降。

## 四、五个反模式（出现过，勿复刻）

1. **批量替换运行时路径**：`02-状态灯链路/` 里 94 处 `.workbuddy` 是镜像内部路径，替换即打断 hooks → 哨兵 → 板子链路。
2. **只改「存 / 读」不做合并语义**：`savePrefs()` 在 `init()` 早期被 `setRange('24h')` / `autoProbe` 调用，会用 `rgb:null` 覆写已存偏好。正确做法是先读旧值再合并写回，且恢复段早于任何回写。
3. **拿老基线当新功能验收**：老 504 项断言不覆盖 W28 新功能，全绿只是「没回归」。
4. **把板端离线判成程序故障 / 用演示值补 0**：来源归属计数在板端不可达时为 0 属正常，须有真实活动才有数。
5. **静默更新基准哈希**：`CANON_BASELINE` 失配时直接改常量会让整套验证失去意义，必须留痕重算。

## 五、诚实边界

- 系统自包含 ≠ 零系统注册：launchd plist、hooks 软链、令牌、应用卡片、线上托管站、烧在板上的固件都在目录之外。
- 100% 零外部残留需要另一套方案（完全磁盘访问 + 改 plist），本项目明确排除。
- 软件 W28 定稿、固件（版本示例 `vX.Y.Z-info`）已烧录并回读一致；按键手感、OLED 目视、断电重启、真机三色等仍属需人工在场验收项。
