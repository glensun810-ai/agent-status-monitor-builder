# 03 · 工程纪律与验证体系

> 这套系统能长期维护，靠的不是某个框架，而是下面这组「约束」。复刻时优先照搬纪律，再照搬代码。

## 一、七条硬纪律

1. **唯一真源**：所有源码、报告、验证只在一个根目录改；其它位置统称「镜像 / 注册点 / 归档」，不承载编辑。与记忆冲突时以磁盘实测为准。
2. **配置单点**：`paths.json` 管路径、`network.json` 管网络；页面里的常整块由脚本生成（BEGIN/END 标记），运行时展示值优先问 `/net`。禁止在 HTML 里散落字面量。
3. **单一同步通道**：真源 → 镜像 → 发布镜像 → 清单，只有 `sync_runtime.py --apply` 能做；`--sync-links` 是显式开关，先备份、逐文件 md5 校验；`--apply` 不重启进程、不改 plist。
4. **清单即事实**：`INVENTORY.json` 自动生成，新增 / 改动文件后先 `--apply` 再体检，否则「清单偏差」会判 FAIL。禁止手改清单。
5. **只读诊断，显式重建**：`health_check.py`（quick / `--full` / `--full --act`）只诊断；`--apply` 才重建；真实板子下发必须 `--act` 且需人工在场。
6. **改功能必补断言 + 留痕**：新增功能 → 补专项断言 → `--apply` → 一次全量复验；若导致 `CANON_BASELINE` 失配，重算并在 `VERSION.md` 留痕，**禁止静默更新**。仅删空白 / 注释不改基准值。
7. **基线不混增量**：老基线（例：504 项 = 450 + W19 54）用于回归；新专项设 `bl=False` 独立判定。老断言「全绿」不覆盖新功能，属「假绿」。

## 二、验证体系分层

| 层 | 内容 | 触发 | 计入基线 |
|---|---|---|---|
| 静态契约 | id 唯一性、button / setInterval / script 计数、内联 JS 语法、契约 json | 每次改动 | 是 |
| 体积预算 | 页面字节上限、最小余量、SW 缓存名与 `budget_revision` 一致 | 每次改 `index.html` | 专项 |
| 端点 / 在线契约 | 生产 8080 / 8420 探活、`/api`、`/net`、`/stats`、`/health` | quick 体检 | 是 |
| 对齐专项 | 前端 / 服务端 / 板端三方状态、work 子态 | `--full` | 是（W19 54 项） |
| 链路自检 | hooks → 状态文件 → 哨兵 → 板，113 项 | `--full` | 专项 |
| 真浏览器 | 三场景、三色往返、偏好刷新回读 | `--full` | 专项，关键 |
| 线上静态站 | 连接向导可达、不误报断线 | `--full` | 专项 |
| 实板下发 | 可逆动作下发 + 回读恢复 | `--full --act` | 39 项按设计未命中，须人在场 |
| 人工目视 | 三入口颜色 9 项、OLED 双屏、按键手感、断电重启、iOS 安全区与深色 | 需人工在场 | 脚本不伪造结论 |

**项数口径**：参考实现一次定稿 `--full` 754/754 PASS、WARN 0、FAIL 0（基线 456 项全命中；48 项按设计未命中）。数字会随功能增长变化，**不硬编码项数**，由各套件实际输出累加。

## 三、环境分级（避免误报）

- **WARN（默认不影响退出码）**：板端断电 / 断网、Chrome CDP 未就绪、状态切换瞬时竞态（复跑通过）、固件版本断言在板端离线时。`--strict` 可收紧。
- **FAIL**：代码、配置、契约、清单、静态断言类失败，并打印明细。
- **复跑机制**：对齐 / 浏览器类失败后隔 2s 复跑一次，通过记 WARN 并留痕，仍失败才判 FAIL。
- **诚实口径**：取不到数据就显示未知 / 0，不用演示值；人工验收项在输出中如实提示差额。

## 四、版本与文档惯例

- `VERSION.md` 用「版本 → 日期 → 关键决策 / 变更」表 + 每版小节；旧文原文不回改，冲突时追加「勘误」小节并注明「增量留痕，原文不回改」。
- 交付报告用 `vX.Y` + 勘误头；过期文档搬 `07-归档/`，不删史料。
- 文档口径统一到现役版本时，历史报告正文保留史实、只加勘误头（需项目方允许回改旧文）。
- README 的「现役状态」表是唯一真值；编年史里的体积 / 按钮数 / 缓存名都是当时的中间值。

## 五、一次改动的标准动作（按顺序）

1. 先跑 `python3 health_check.py`（只读），确认起始状态干净。
2. 只改必要的文件；配置类改动落在 `network.json` / `paths.json`。
3. 补对应专项断言，命名 `verify_wXX.py`，并在体检中注册（`bl=False`）。
4. `python3 sync_runtime.py --apply`：重建页面生成块 → 镜像 → 发布镜像 → INVENTORY → 预算自检。
5. 跑一次 `health_check.py --full`，确认 PASS / WARN / FAIL 与预期一致。
6. 涉及偏好、缓存、初始化顺序、SW 的改动，追加真浏览器「改值 → 刷新 → 回读」往返。
7. 在 `VERSION.md` 追加决策留痕；若基准哈希失配，同时记录重算前后值。
8. 明确列出「需人工在场项」，不替人签字。

WS/SSE 架构改造、云服务、账户鉴权、原生打包、git 入库（新目录在 git 根外）、完全磁盘访问的零镜像方案（B 方案）。三期计划（体检 → 增强 → 瘦身）已完成，后续均为按真实需求驱动的单点增量。
