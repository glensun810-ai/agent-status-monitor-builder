# 05 · 从零搭建操作手册

> 目标：在另一台机器 / 另一个团队里，按同一套纪律搭出可日常使用的 Agent 状态监控小系统。参考实现现役 W29（2026-11-16）。
> 前置：macOS（或等价的本地服务环境）、Python 3、一块 ESP32-S3 + 三色灯 + 0.96″ OLED、Arduino CLI/IDE、同一 WiFi 的手机。

## Step 0 · 先划边界

先写清三件事，再写第一行代码：

1. **数据源**：Agent 运行时的 hooks / 适配器产生事件，落到本地 `jsonl` 与状态文件；不接云端、不做账户体系。事件流水在运行时镜像下，**不在真源目录**。
2. **展示与控制**：本机 `8080` 单文件看板，手机走同 WiFi；状态灯门户 `8420`；板载 AP 作无电脑应急入口。
3. **诚实口径**：取不到数据就显示「未知 / 离线」，不生成演示值；`dur_s` 是相邻状态跃变间的任务周期，不是 AI 思考时长 / 人工工时；不完整自然日不做日环比；人工物理验收单列，脚本不代签。

同时明确排除项：WS/SSE 改造、云服务、鉴权、原生打包、完全零镜像方案、**固件网页配网**（SSID 硬编码，换 WiFi 须改 `config.h` 重编译烧录）、**无数据支撑的月 / 季热力图跨度**（须先做事件按月归档）。

另定体积预算：护栏值 + `min_headroom_bytes` 写入验证脚本与 manifest，算出硬上限；后续任何新增功能先核余量，按实测安全压缩上限报价，不放宽护栏。

## Step 1 · 生成目录骨架

```bash
python3 ~/.workbuddy/skills/agent-status-monitor-builder/scripts/scaffold.py \
  --target /path/to/agent-status-monitor
```

骨架包含 `01-核心界面/` ~ `08-视频号/`、`README.md`、`VERSION.md`、`04-验证/baseline.md`、脱敏后的 `paths.json` / `network.json`。

若本机已有一套可参考的真源实现，加 `--from <真源目录>` 复制代码层（默认跳过史实文档、素材、密钥与缓存）：

```bash
python3 ... --target /path/to/new --from /path/to/reference-truth
```

复制后**立即执行 Step 2 的脱敏清单**，否则会把别人的 IP、令牌、sharecode 与固件 WiFi 凭据带进新项目。

## Step 2 · 配置与脱敏

只改 `network.json` 的 `params`：`local_url` / `portal_api` / `lan` / `host` / `board_ip` / `port_suffix` / `ap_ssid` / `ap_url` / `board_mdns`。路径改动只改 `paths.json`。

必查替换项：`secrets.h` / `config.h`（WiFi SSID 与密码，用 `.example` 重建）、`lan_token`、`sharecode`、访问码、应用卡片 `.genie`、线上站点 host / `app_id`、发布镜像绝对路径、历史 git 路径、门户兼容开关、`INVENTORY.json` / `CANON_BASELINE` / 验证项数 / 体积护栏。运行时事件流水与会话台账不复制、不外发。

`ap_ssid` 必须与固件 `config.h` 一致；固件无网页配网，前端向导只做同网判定与指路。

> 页面内网络常量必须由 `network.json` 生成（BEGIN/END 标记块）；运行时展示值优先调 `/net`。禁止把 IP 写死进 HTML。

## Step 3 · 打通最小数据闭环

1. 让 hooks / 适配器把「谁在执行、什么状态、何时发生」写进本地事件文件（字段参考 `ts/kind/src/dur_s/seq`，2s 采集、状态跃变才写）。
2. 写一个哨兵进程：事件驱动读取 → 归一成状态 → 下发板端；附带短超时与失败回落，不阻塞 Agent 主流程。
3. 用 `04-验证/` 的链路自检覆盖「hooks → 状态文件 → 哨兵 → 板」四段（参考实现 113 项），逐段给可断言的结果。

验收点：手动改一次状态文件，灯与屏在预期时间内变化；断掉哨兵后板端**灭灯**（失效保护），不残留假状态。

## Step 4 · 8080 服务与单文件看板

1. `wb_board_server.py` 自包含 HTTP 服务：静态页 + `/api` `/stats` `/events` `/audit` `/net` `/health` `/ctl` `/align` `/preview`。`/stats` 自带**逐条 csv 明细**（`ts,kind,src,dur_s,seq`），供热力图按真实数据聚合，无需另开后端。
2. `index.html` 单文件 SPA：三档轮询 + 失败翻倍退避 + 页面隐藏暂停；断流宽容窗口 15s；单次失败不立刻切 OFFLINE。
3. 连接状态用**单一出口**（参考 `renderLinkState()`）驱动全部提示容器；监控暂停用**单一 setter**（参考 `setMonitorPaused(v)`）并同步 `aria-pressed`。避免同一状态四处各写 DOM、双实现文案不一。
4. 换网向导（纯前端）：用 `/net` 的 `ip` / `lan_url` 与 `/api` 的 `ip` / `ssid` / `rssi` 判同网；板端失联 / `file` / `static` / 演示四态分别给文案；明确固件无网页配网；救援 AP 指路；不新增 id / button / 定时器（用 class 选择器）。
5. 热力图多维度：优先取 `/stats` 的 csv 逐条明细，用单一渲染出口聚合；按首末事件算**真实覆盖天数**并诚实标注「数据积累中，暂不绘满」；空维度不绘推测数据；来源命名遵守术语表（参考实现只认 **TRAE CN** / `trae`）。数据不足时**不做月 / 季选项**。
6. `sw.js` + `manifest.json`：离线缓存、缓存名随版本 bump，并与 `budget_revision` 一致。
7. 建立计数契约：id 全唯一、button / setInterval / style / script 计数固定并做成断言；新功能复用唯一 `tick`，不新增定时器；设置项状态反馈的 elId 必须指向**真实存在的 DOM**，并写「提取全部 elId → 比对 DOM id 集合」的通用断言。

验收点：断网时页面显示降级态而非伪造数据；恢复后自动折半回到快档；真浏览器刷新后偏好保持。

## Step 5 · 8420 门户与板端下发

- 门户负责发现（mDNS / AP / DHCP / 直连）、访问码配对（`POST /__pair` 确认后才种 Cookie，令牌文件 0600）、控制动作白名单透传。
- 所有 `POST /ctl` 经 8080 同源代理下发，**成败以回读为准**，不用前端本地猜测。
- 来源归属用 `/agents` 明细按本轮 `ago` 最小归属，短超时 + 好值缓存，失败回落聚合值；板端不可达时计数如实为 0。

验收点：手机首次访问带码链接 → 确认配对 → 30 天免码；轮换令牌后旧 Cookie 立即失效。

## Step 6 · 固件（物理资产）

1. 编译校验 EXIT=0；`FW_VER` 单值标识。
2. NVS 保存三色与音量（`wb_bv` 是蜂鸣器/功放音量，**不是总亮度**），上电读回；保留无心跳强制灭灯。
3. 中文显示按 UTF-8 字符边界裁剪；板载 AP 页内嵌于固件，改页须重烧；推送文本用 ASCII 短码（板端缓冲仅 31 字节），含义在前端 toast 解释。
4. **固件默认无网页配网**：SSID / 密码硬编码 `config.h`，换 WiFi 改文件重编译烧录；前端不得承诺可配网。
5. 烧录四步：整片备份 → 只写 `0x10000` 应用分区 → 读回 md5 一致 → `/api ver` 回读一致。烧录失败先查数据线是否支持传数据。
6. 回退路径写进 `03-固件/flash.md`，附实测记录；勿恢复已撤销的门户颜色交换开关。

## Step 7 · 唯一真源与同步通道

- 编辑只发生在真源目录；运行时镜像放在系统可读位置（macOS 下 `~/.workbuddy/wblight/`）。
- `sync_runtime.py` 实现：`--check` 只读比对 / `--apply` 重建（生成块 → 镜像 → 发布镜像 → `INVENTORY.json` → 预算自检）/ `--rollback` / `--sync-links`（显式开关，先备份逐文件校验）。
- `--apply` 不重启进程、不改 plist；`INVENTORY.json` 禁止手改；同步脚本**不回写 README 现役真值表**。
- 发布镜像若绑定了平台应用卡片，保持原目录路径以复用链接，不另发第二个应用。

## Step 8 · 验证体系与一键体检

1. 建基线：静态契约 + 端点 / 在线契约 + 对齐专项，项数由各套件输出累加，不硬编码。
2. 每加一个功能建 `verify_wXX.py` 专项，设 `bl=False` 独立判定，不混入老基线；断言必须校验真实运行时对象，禁止只查源码字面量。参考实现 W29 专项 101 项（含「全部 patchConfig 状态 elId 必须在 DOM 中存在」通用契约）。
3. `health_check.py`：**默认即 quick 只读**（无 `--quick` 参数）/ `--full` 全量（链路自检、真浏览器、线上）/ `--full --act` 实板下发 / `--strict` 收紧 WARN；环境态 WARN、程序故障 FAIL；对齐与浏览器失败隔 2s 复跑一次。
4. 涉及偏好 / 初始化顺序 / 缓存的改动，追加真浏览器「改值 → 刷新 → 回读」往返。
5. 设体积护栏（上限 + 最小余量）写进验证脚本与 manifest；改版同步 bump SW 缓存名。近预算时**先落地后压缩**：压缩器带字面量保护、默认 dry-run、`--apply` 才写盘；压缩后按「下一个 `function`」锚定提取函数体，并复跑全部 `verify_*.py` 与三段内联 JS `node --check`。
6. 专项断言标题一旦被其他脚本硬匹配（如「标题已同步 WXX」），只改基准常量、勿改标题。

## Step 9 · 日常运维与留痕

```
python3 health_check.py                 # 先诊断（默认 quick，只读）
python3 sync_runtime.py --check         # 清单 / 镜像比对
# 改动 → 补断言 → 下面两条
python3 sync_runtime.py --apply
python3 health_check.py --full
```

每次改动在 `VERSION.md` 追加决策留痕；基准哈希失配要重算并记录前后值；**README 只维护一张「现役状态」表且须手工同步**。收尾列出「需人工在场项」，不替人签字。预计 >50 轮推理 / 读入 >200KB / 一个请求含 3+ 互不相关子任务时，先报价等确认、另开会话。

## macOS 特别注意

- launchd 无 `~/Documents` TCC 授权 → 运行时必须读镜像；plist 真正生效位置是 `~/Library/LaunchAgents`，项目内 `05-运行配置/` 只作只读存档。
- `launchctl bootstrap/load` 在某些 namespace 会失败（服务可能由宿主应用持有）；先查托管进程与镜像同步状态，不盲目重启。参考实现曾由 临时 keepalive 脚本 自愈托管，18:35 已正规化为 launchd 常驻（`RunAtLoad` + `KeepAlive(SuccessfulExit=false)`，kill 后 12s 自动拉起实测通过），keepalive 已退出无残留 —— 排障时先查 launchd 服务状态与镜像同步。
- 授予「完全磁盘访问」可消除镜像，但属于另一套方案，本项目明确排除。
- 真浏览器自动化：Playwright 自带 chromium 若缺 headless shell，改用本机 Chrome 的 `executablePath`，勿反复试默认 launch。
